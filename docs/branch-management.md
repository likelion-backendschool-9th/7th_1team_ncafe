# 지점 관리 실행 및 확인

## 실행

프로젝트 루트에서 터미널 두 개를 사용한다.

```bash
cd backend
bash gradlew bootRun
```

```bash
cd frontend
npm install
npm run dev
```

화면: `http://localhost:3000/admin/branches`

프런트엔드의 `/api/v1/branches`, `/api/v1/admin/branches`, `/api/v1/auth` 요청은
Next.js rewrites를 통해 기본적으로 `http://127.0.0.1:8080`에 전달한다.
백엔드 주소가 다르면 `BACKEND_URL`을 지정하고 프런트엔드를 재시작한다.
프로덕션 빌드에서는 빌드 시에도 해당 값을 지정한다.

```bash
BACKEND_URL=http://127.0.0.1:8081 npm run dev
```

## 인증 연동

새 로그인 화면이나 테스트 계정은 추가하지 않았다. 기존 회원 담당의 세션 인증 API를 사용한다.

- 로그인: `POST /api/v1/auth/login` (`loginId`, `password`)
- 로그인 확인: `GET /api/v1/auth/me` (응답의 `role`이 `ADMIN`이어야 편집 가능)
- 로그아웃: `POST /api/v1/auth/logout`

로그인 요청은 프런트엔드와 같은 출처의 `/api/v1/auth/login`을 통해 호출해
세션 쿠키를 사용해야 한다. 프런트엔드와 백엔드의 호스트명을 혼용하지 않는다.
로그인 후 지점 화면에서 **목록 새로고침**을 누르면 권한을 다시 확인한다.
현재 브랜치에는 로그인 UI가 없으므로 회원 담당의 로그인 화면 연결이 별도로 필요하다.
관리자 계정 준비도 회원 담당과 맞춘다. 권한 승격 API나 기본 관리자 계정은 만들지 않았다.

비로그인/일반 회원은 목록 조회만 가능하다. 백엔드도 등록·수정을 관리자에게만 허용한다.
세션이 만료되면 입력값을 유지하며 저장을 막고 재로그인을 안내한다.

## 지점 API

| 기능 | 메서드 | 경로 |
|---|---|---|
| 전체 목록 (ID 오름차순, 영업 종료 포함) | GET | `/api/v1/branches` |
| 상세 | GET | `/api/v1/branches/{id}` |
| 관리자 등록 | POST | `/api/v1/admin/branches` |
| 관리자 수정 | PUT | `/api/v1/admin/branches/{id}` |

등록 예시:

```json
{
  "id": "mapo",
  "name": "마포 본점",
  "address": "서울시 마포구",
  "sections": "[]",
  "fixtures": "[]",
  "open": true
}
```

- ID는 영문·숫자·완성형 한글·밑줄·하이픈 1~255자이며 수정할 수 없다.
- 이름 1~100자, 주소 1~255자, 영업 여부는 필수다.
- `sections`, `fixtures`는 JSON 배열을 담은 **문자열**이다. 생략/빈 값은 `"[]"`로 저장한다.
- 평면도 내부 좌표와 필수 항목 검증은 아직 없으며 좌석 담당과 스키마 합의가 필요하다.
- PUT은 전체 교체다. 본문에 ID·등록일은 보내지 않으며 평면도를 생략하면 빈 배열로 바뀐다.
  관리 화면은 수정 시 기존 평면도 값을 그대로 불러와 함께 전송한다.
- 응답은 `id`, `name`, `address`, `sections`, `fixtures`, `open`, `createdDate`를 포함한다.
- 주요 오류: 400 입력 오류, 401 비로그인, 403 권한 부족, 404 없는 지점, 409 중복 ID.

## 확인 순서

1. 비로그인 상태에서 목록 확인, 등록·수정 버튼 비활성화 확인.
2. 관리자 세션으로 목록 새로고침 후 지점 등록.
3. 새로고침해도 등록 데이터가 조회되는지 확인.
4. 지점명·주소·영업 여부 수정 후 재조회. ID·등록일·기존 평면도 유지 확인.
5. 검색, 영업 상태 필터, 빈 검색 결과, 중복 ID 오류, 잘못된 평면도 입력 확인.
6. 일반 회원 권한 거절과 로그인 만료 안내 확인.
7. 모바일 폭에서 목록과 폼 확인.

```bash
# backend
bash gradlew test

# frontend
npm run lint
npm run build
```

H2 메모리 DB는 **백엔드 종료 시 초기화**된다. 새로고침 시 유지되는 것과 서버 재시작 후
유지되는 것은 다르다. PostgreSQL 실행 검증은 아직 진행하지 않았다.

좌석 예약 화면의 임시 지점 데이터는 변경하지 않았다. 좌석 담당과 ID 및 평면도 형식을 맞춘 뒤
사용자용 지점 조회 API로 연결할 예정이다.
